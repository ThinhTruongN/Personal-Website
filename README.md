# Personal Website

Projects, research, publications and competitive-programming progress. Plain HTML/CSS/JS — no build step — hosted on GitHub Pages.

## Competitive programming data

`data/cp.json` is generated by `scripts/fetch-cp-data.mjs` (Node 18+, no dependencies) from:

| Source | What | API |
|---|---|---|
| Codeforces | rating history, unique problems solved per day, solved by difficulty | `codeforces.com/api` |
| AtCoder | rating history, unique problems solved per day | `atcoder.jp/users/<handle>/history/json`, [AtCoder Problems API](https://github.com/kenkoooo/AtCoderProblems) |
| LeetCode | contest rating history, solved by difficulty, submissions per day | `leetcode.com/graphql` |
| Google Sheet | CSES and USACO Guide progress (rows with `SOLVE = Yes`) | public CSV export |

A GitHub Action (`.github/workflows/update-cp-data.yml`) re-runs the script every day and commits the result, so the site stays current — AtCoder and LeetCode block browser requests, which is why the data is fetched server-side.

Notes:
- **LeetCode daily counts are submissions**, not unique solves — LeetCode doesn't expose per-day solves publicly.
- **"Problems solved"** is de-duplicated across Codeforces, AtCoder, CSES and the USACO Guide sheet by problem link; LeetCode's count is added on top.
- The spreadsheet must stay shared as "Anyone with the link can view".

### LeetCode per-problem list (one-time)

LeetCode only shows your solved-problem list to you while logged in, so it's imported once from your own machine:

```sh
node scripts/leetcode-backfill.mjs   # paste your LEETCODE_SESSION cookie at the hidden prompt
node scripts/fetch-cp-data.mjs
```

This writes `data/leetcode-solved.json` (problem names and dates only — the cookie is never saved). From then on the daily Action adds new solves from your public "recent 20 accepted" list. Problems are rated with [zerotrac's contest-problem ratings](https://github.com/zerotrac/leetcode_problem_rating), converted to the Codeforces scale; non-contest problems stay unrated. If you ever solve more than 20 LeetCode problems in one day, re-run the backfill.

### Configure

Edit `config.json`: set your handles, and optionally `timezone` (an IANA name like `America/New_York`) so days are bucketed in your local time.

### Run locally

```sh
node scripts/fetch-cp-data.mjs     # refresh data/cp.json
python3 -m http.server 8000        # then open http://localhost:8000
```

(Opening `index.html` directly from disk won't work — browsers block `fetch` on `file://`.)

## Deploy

1. Push to `main`.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Settings → Actions → General → Workflow permissions: **Read and write permissions**.
4. Actions → *Update data and deploy site* → **Run workflow** once.

After that the workflow runs every day at 06:17 UTC (and on every push): it refreshes `data/`, commits it, and redeploys the site. Note that GitHub pauses scheduled workflows in repos with no activity for 60 days — if that happens you'll get an email, and one click on "Enable workflow" in the Actions tab resumes it.
